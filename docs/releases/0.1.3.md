# KeepCV 0.1.3

This release publishes the reusable browser editor, adds safe PostgreSQL owner
lifecycle operations and includes the security and editing fixes since 0.1.2.

## Reusable editor

`@keepcv/editor@0.2.0` is the first published editor package. Mount `Editor` with
the typed API client, a QueryClient and an optional sign-out callback. It includes
compiled styles, icons, a theme script and the DOCX worker. The local web app
uses this same entry. An isolated consumer installs the packed packages,
typechecks and builds without Tailwind source scanning, and exercises keyboard
navigation, profile writes, the supplied cache and sign-out.

The entry owns browser history at the origin root. See the
[editor guide](../../packages/editor/README.md) for asset handling and cache
ownership when changing owners.

## PostgreSQL lifecycle

`@keepcv/db@0.2.0` adds atomic, idempotent `provisionOwner` and a separate
`eraseOwner(id, { erasePermanently: true })`. Concurrent retries preserve existing
data and recover after failures. Permanent erasure removes all owned content
and history in one transaction and leaves other owners intact, even when native
imports used identical ids.

The server adapter accepts connection limits, acquisition/startup and idle
timeouts, a statement timeout and validated TLS CA configuration. Certificate
checks use the configured DNS name or IP; connection-string SSL parameters
cannot overwrite the hostname check. Migrations use the same connection as
their advisory lock, including with a pool of one. Shutdown drains active work
and is safe to await repeatedly.

Repository isolation continues to use ambient owner predicates. No RLS policy
is installed. Lifecycle operations are outside the content API; callers stop
admitting work before erasure and remove separately held backups themselves.
See the [database guide](../../packages/db/README.md).

## Security fixes

- Revoke running password sessions when credentials change and bound concurrent
  sign-in attempts, request bodies and imported browser files.
- Validate launcher Host and Origin before routing, require a declared public
  origin for network binds, and apply a same-origin Content Security Policy.
  Keep private API responses out of caches.
- Protect launcher data and native backups with private filesystem permissions.
- Reject fetching CSS in new designs after decoding escapes. Preserve older CSS
  in native archives while omitting unsafe CSS from renders with a warning.
  Exported HTML and portfolio files include a Content Security Policy.
- Bound DOCX inflation and move Word extraction to a cancellable browser worker.
- Update dependencies with security fixes and exclude source/declaration maps
  from published packages while retaining runnable code and declarations.

## Editing and exports

Current-resume exports are recorded in history and history capture refuses a
stale preview. Phrasing edits and recovery preserve formatting; settings retain
pending changes across navigation and failed saves. Phrasings have comparison
and reapply controls, and import review distinguishes repeated titles.

## Versions and running

The launcher and the seven libraries other than the editor and database use
0.1.3. The editor and database use 0.2.0. There are ten public packages in this
release; the web app remains private.

With Node 24 or newer, after publication:

```sh
npx --yes @keepcv/cli@0.1.3 serve
```

Open the complete URL printed by the launcher. Existing stores use the same
schema; this release adds no destructive migration. Keep a native backup before
large imports or permanent erasure. Archiving remains reversible and does not
erase content.

## Verification

The full checks cover both PGlite and PostgreSQL, including concurrent owners,
identical imported ids, denied cross-owner access, provisioning and erasure
recovery, TLS trust and hostname validation, limits, timeouts and shutdown.
Removing owner isolation, provisioning, erasure and TLS guards makes the relevant
regressions fail. Installed-package checks exercise the editor and lifecycle
entry points, plus launcher authentication, writes, six export paths, backup
and restore. The release workflow verifies and publishes those exact tarballs
with provenance after registry preflight and environment approval.
