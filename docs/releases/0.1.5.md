# KeepCV 0.1.5

This release gives reusable editor and API consumers control over browser edit
recovery and unexpected-error reporting.

## Connected-store recovery

`Editor` accepts an optional `recoveryNamespace`, a stable opaque string chosen
by its caller for the connected store. Pending wording, template designs and
resume settings stay with that store even when imported ids overlap. Failed
saves and sign-out retain pending edits; reopening the same namespace recovers
its own contents.

Omitting the namespace retains standalone recovery, including existing
unscoped copies. Scoped connections leave those legacy copies untouched because
their store cannot be inferred safely. Theme and navigation preferences remain
shared. See the [editor guide](../../packages/editor/README.md).

## Unexpected-error reporting

`createApi` and `problemFor` accept optional `reportUnexpectedError`. Omission
retains console reporting; `null` disables it; a callback lets the consumer
choose what is safe to report from the original error. Reporter throws and
rejected promises do not replace client problems or produce fallback output.

Generic 500 responses and expected validation, conflict, stale-write, restore
and export-change problems retain their existing behavior. Expected problems
do not invoke the reporter. See the [API guide](../../packages/api/README.md).


Open the complete URL printed by the launcher. Existing stores use the same
schema; this release adds no database migration.

## Verification

Recovery tests switch between stores with identical native ids, preserve failed
edits through sign-out, recover each store's own text and settings, and retain
legacy standalone recovery. Installed-package tests restore the same native
archive into two stores and exercise all three recovery paths through the
published editor entry.

API tests cover disabled and custom reporting, synchronous and asynchronous
reporter failures, concurrent consumers, and unchanged expected problems.
Installed-package tests verify configured reporting without raw console output.
The release checks cover launcher writes, exports, backup and restore; CI runs
both database drivers and verifies exact tarballs before publication.
