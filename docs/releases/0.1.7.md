# KeepCV 0.1.7

This release adds opt-in transaction cancellation and restores large native
archives atomically on PostgreSQL and PGlite.

## Transaction cancellation

`UnitOfWork.run(work, { signal })` accepts native AbortSignal objects through
the exported structural CancellationSignal and UnitOfWorkOptions types. Existing
callers can omit options. API content transactions forward the incoming Request
signal; the host connects transport disconnects and deadlines to that Request.

Server PostgreSQL removes cancelled acquisition waits, interrupts connection
startup and the actual checked-out query, and refuses late statements. Callbacks
are never replayed. The first observed operation error or cancellation survives
rollback failure. Cancellation uses a separate authenticated control connection
outside the work pool's maximum; configure database connection capacity for it.

Once COMMIT is dispatched, abort cannot promise rollback. A confirmed commit
succeeds; a lost reply can still mean the write committed. Re-read before
retrying authored work after an ambiguous disconnect. A late abort cannot affect
later work after connection reuse. Independent units and lifecycle operations
do not inherit a request signal. PGlite observes cancellation at transaction and
callback boundaries without preempting an in-process statement or caller code.

## Large native archives

Every native-loader INSERT is bounded by its emitted parameter count: 65535 on
server PostgreSQL and the effective 32767 ceiling of PGlite 0.5.4. Every batch and
table remains inside one owner-scoped transaction. A later failure rolls back
earlier batches. Native ids, all historical Revisions, canonical phrasings and
current Revision pointers are preserved, with the existing empty-store policy.

```sh
npx --yes @keepcv/cli@0.1.7 serve
```

Open the complete URL printed by the launcher. Existing stores use the same
schema and native format; this release adds no database migration.

## Verification

Real PostgreSQL tests coordinate acquisition, query and COMMIT races with
observed barriers, including password authentication, rollback failure and pool
reuse. Parameter probes exercise every native INSERT table below, at and above
its effective boundary. Large roundtrips and later-batch failures run on both
database backends. Isolated installed-package tests create and export 2000 and
3000 Points with three Revisions each, import them for concurrent owners, and
verify full history, owner isolation and API cancellation through public entries.
Release validation checks the complete package set, launcher round trips and
exact tarball integrity before publication.
